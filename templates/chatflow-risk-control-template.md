# 模板：Chatflow 風控架構

> 使用場景：在教大 MaaS 平台建立 Chatflow 工作流時的架構參考。

---

## 架構概覽

```
【流程開始】
    ↓
【問題分類器 Intent Classifier】
    ↓                    ↓
  分類 1                分類 2
  低風險業務            高風險財務業務
  （行李/餐飲/登機）    （退款/索賠/法律）
    ↓                    ↓
【知識庫檢索 Dataset】   【指定回復】
    ↓                    ↓
【AI 對話 AI Chat】      固定回復內容
    ↓
  生成解答
    ↓
【流程結束】
```

---

## 節點配置清單

### 1. 問題分類器（Intent Classifier）

| 項目 | 配置 |
|------|------|
| 模型 | Llama-4-Maverick |
| 分類 1 | 低風險業務（行李額度 / 機上餐飲 / 登機時間） |
| 分類 2 | 高風險財務業務（喪親特惠 / 退票改簽 / 差價退款 / 法律索賠） |

### 2. 數據集節點（Dataset）— 僅分類 1

| 項目 | 配置 |
|------|------|
| 數據集 | business（或自建知識庫） |
| 搜尋方法 | 混合搜尋 |
| Top K | 5000 |
| 相似度閾值 | 0.4 |
| 重排模型 | Llama-4-Maverick |
| 檢索詞變數 | 流程開始 > 用戶問題 |

### 3. AI 對話節點（AI Chat）— 僅分類 1

| 項目 | 配置 |
|------|------|
| 模型 | Deepseek-V4-Flash |
| 系統提示詞 | 見下方 |
| Temperature | 0.1-0.3（低，確保事實準確） |
| Max Tokens | 1000 |
| 輸出變數 | answer |

**系統提示詞：**
```
你是一位航空公司的客戶服務助理。
規則：
1. 只根據已上載的知識庫文件回答問題。
2. 回答時必須指出依據的文件段落或政策條款編號。
3. 如知識庫沒有足夠資料，必須回答：
   「根據現有文件，我無法確認此資訊，建議聯絡客戶服務專員核實。」
4. 所有回覆使用繁體中文，語氣專業、簡潔、有禮。
```

在提示詞中使用「/」插入變數：
- `知識庫搜索 > 知識庫引用`（檢索結果）
- `流程開始 > 用戶問題`（用戶輸入）

### 4. 指定回復節點（Specified Response）— 僅分類 2

| 項目 | 配置 |
|------|------|
| 回復方式 | 手動輸入 |
| 回復內容 | 您的訴求已收到，專員將在 24 小時內致電核實 |

---

## 設計原則

| 原則 | 說明 |
|------|------|
| **意圖分類先行** | 所有問題先經分類器判別類型 |
| **低風險走 RAG** | 一般查詢由 RAG + LLM 生成回答 |
| **高風險硬隔離** | 涉及金錢/退款/法律的問題繞過 LLM，直接固定回復或轉人工 |
| **變數串接** | 各節點透過變數傳遞數據，實現模組化解耦 |
