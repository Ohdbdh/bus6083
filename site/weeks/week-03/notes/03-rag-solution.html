3. RAG 作為解決方案

本節定位

  • 上一節：LLM 幻覺導致 Air Canada 承擔法律責任
  • 本節要解決的問題：如何讓 AI 基於事實回答，同時保留可追溯的證據鏈？
  • 學完你應該能夠：定義 RAG、用開卷考試比喻解釋其原理，並說明它如何對應解決上一節的三個風險
  • 關鍵詞：檢索增強生成（RAG）、向量嵌入（Embedding）、審計追溯

從「自由回答」到「有憑有據地回答」

前兩節看到了兩個極端：Klarna 用 RAG + API 取得成功，Air Canada 讓 LLM 自由回答導致法律責任。業界的共識是——需要一種架構，讓 AI 基於事實回答，而非自由生成。這正是 RAG 要解決的問題。

RAG 精準對應三個風險

上一節指出 LLM 自由回答有三個問題。RAG 正是針對這三點設計的：

風險（Note 2）RAG 如何回應
知識過時（Knowledge Cutoff）從外部知識庫動態檢索最新資訊，而非依賴訓練時的舊知識
自由編造（幻覺）強制模型根據檢索到的內容回答，而非憑空生成
無法追責每次回答都保留具體來源段落，可精確追溯

何謂 RAG？

檢索增強生成（Retrieval-Augmented Generation, RAG）：一種系統架構，透過從外部知識庫動態檢索相關資訊，並將其作為上下文輸入，從而增強 LLM 的輸出準確度。

最早於 2020 年由 Patrick Lewis 等人正式提出。

  • 論文：Lewis, P., et al. (2020). *Retrieval-Augmented Generation for Knowledge-Intensive NLP Tasks*. NeurIPS.

開卷考試比喻

模式比喻說明
傳統 LLM閉卷考試的資優生通曉通識，但面對具體或冷門的專業細節，會胡亂猜測甚至憑空捏造答案
RAG 增強的 LLM開卷考試的資優生同樣聰明，但落筆前可以查閱官方教科書與指引以核實資料

RAG 不改變 LLM 本身的能力，而是為它提供了一個「可以查書」的機制。

RAG 的核心價值

1. 零重新訓練成本

當企業內部政策調整時，毋須耗費數百萬美元重新訓練 LLM——只需上載最新的 PDF 文件即可更新知識庫。

2. 大幅節省時間

將雜亂、非結構化的 PDF 文檔瞬間轉化為可即時查詢的知識資產，節省成千上萬的人工工時。

3. 來源引註與審計追溯

這是企業 AI 採用 RAG 的關鍵原因,直接回應上一節「責任由誰承擔」的問題。一旦 AI 提供了錯誤建議，企業必須能查明成因。由於 RAG 每次均檢索具體的文檔區塊，開發者能精確追溯 AI 是依據哪一段原文生成回覆，從而實現精準排錯與審計。

RAG 的代表性應用

Perplexity 是將 LLM 結合即時網絡檢索的代表性產品，透過 RAG 機制自動整合資料並標註引用出處，帶動了 Copilot 及 Google AI Overview 等同類產品的發展。

應用場景

RAG 適用於需要「高準確度、具事實依據、可追溯來源」的領域：

  • 市場研究
  • 法律諮詢
  • 學術文獻檢索
  • 產品比對
  • 企業客服（如 Klarna）

思考題

  • 如果沒有 RAG，企業要讓 LLM 知道最新的政策，還有什麼替代方法？各有什麼缺點？
  • 「審計追溯」對於一般消費者產品（如聊天 App）重要嗎？對於金融或醫療產品呢？
