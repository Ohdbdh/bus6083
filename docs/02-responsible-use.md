# 模組二：負責任使用

## 1. Klarna AI 客服案例

### 商業背景與業務痛點
- **業務規模**：Klarna 服務全球 1.5 億活躍消費者及 50 萬合作商户，橫跨數十個國家與語種
- **痛點危機**：海量重複性客服諮詢（查賬單、退換貨、分期展期），跨時區客服團隊成本極高，人工平均解決時間長達 **11 分鐘**
- **解決方案**：2024 年初全面部署接入 OpenAI 技術的企業智能客服助手，覆蓋 35 種語言、24/7 全天候響應

### 商業成效數據
| 指標 | 數據 |
|------|------|
| 處理量 | 上線首月獨立處理 **230 萬次**對話，佔全公司客服量的 **67%** |
| 人力等效 | 相當於 **700 名**全職客服 |
| 重複諮詢率 | 下降 **25%** |
| 解決時間 | 從 11 分鐘大幅降至 **2 分鐘以內**（縮短 80%） |
| 財務回報 | 單年為公司帶來 **4,000 萬美元**（約 3.1 億港元）利潤改善 |

來源：[OpenAI 官方案例](https://openai.com/index/klarna/)

## 2. Klarna 的成功秘訣

### 為什麼 Klarna 不會滿嘴胡話？
- 它**不是一個放任自由聊天的 ChatGPT**
- 核心支柱：掛載了實時更新的**企業知識庫（RAG）**與嚴格**業務系統接口（API）**
- 能夠精準調取用户賬單、官方退貨條款與銀行扣款規則，做到有憑有據、按章作答

### 2025 年轉折：降本走得太快引發的警示
- **組織陣痛**：Klarna 隨後凍結了常規招聘，員工數從 5,000 縮減至 3,000 多，引發巨大社會與員工心理震盪
- **體驗瓶頸**：2025 年，CEO 承認在客服全自動化上「走得太遠」——當客户遭遇複雜金融爭議、被盜刷或需要情感撫慰時，AI 的機械回答引發嚴重客訴
- **調整方向**：Klarna 重新啟動真人客服招聘，確立**「AI 負責標準件，人類負責複雜件」**的混合協作架構（Human-in-the-Loop）

## 3. 加拿大航空（Air Canada）個案

### 事件經過
2022 年，一名乘客透過加拿大航空網站的聊天機械人查詢「喪親特惠機票」。

### 關鍵時間線
| 階段 | 內容 |
|------|------|
| 機械人回覆 | 乘客可在完成旅程後追溯申請相關折扣 |
| 官方條款 | 機械人附上的官方政策連結卻明確列明：旅程一旦結束，概不接受追溯申請 |
| 航司抗辯 | 加拿大航空辯稱該聊天機械人為「獨立法人實體」，需自負責任，公司毋須為其言論承擔法律責任 |
| 裁決結果 | 2024 年，加拿大卑詩省民事審裁處裁定：**加拿大航空必須為其網站聊天機械人提供的錯誤資訊承擔法律責任** |

### 核心癥結（課堂討論）
- 這純粹是人工智能的「幻覺」問題？
- 還是整體業務流程根本缺乏關鍵的風控機制？

## 4. 負責任使用原則總結

從 Klarna 與 Air Canada 兩個案例中，我們可以總結出以下原則：

| 原則 | 說明 |
|------|------|
| **RAG 為基礎** | AI 必須基於知識庫的事實回答，而非自由生成 |
| **來源可追溯** | 每個回答都應能追溯到具體文檔段落 |
| **人機協作** | AI 處理標準化問題，複雜問題轉交人類 |
| **法律責任** | 企業必須為 AI 系統的輸出承擔法律責任 |
| **風控隔離** | 高風險業務（退款、法律）不應完全交由 LLM 處理 |
