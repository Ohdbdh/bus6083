# 模組四：聊天機械人構建

## 1. 建立聊天機械人

點擊「新建」（New），選擇「對話代理」（Dialogue Agent），並輸入應用名稱。

---

## 2. 介面配置

| 配置項 | 說明 |
|--------|------|
| **AI 模型** | 選取合適的模型（若系統出現報錯，可改選 DeepSeek V4 Flash 或 Meta Llama 等輕量／備用模型） |
| **系統提示詞** | 於設定區內編寫模型的角色定位、規範與運作指引 |
| **數據庫** | 關聯並選取所需的知識庫數據集 |
| **檔案上載** | 開啟或關閉對話時允許用户上載文件的功能 |
| **開場白** | 設定聊天機械人啟動時的預設歡迎訊息 |
| **語音功能** | 啟用語音播放（TTS）及語音輸入（STT）支援 |

## 3. 模型調校（AI Model Configuration）

### 最大生成長度（Max Tokens）
限制模型單次回覆所能生成的最大長度（Token 上限）。

### 溫度值（Temperature）
控制文本生成的隨機度與創意空間。

| 數值 | 效果 | 適用場景 |
|------|------|----------|
| **低數值** | 輸出結果高度確定、嚴謹 | 以事實為導向的場景 |
| **中等數值** | 在流暢度與準確度之間取得平衡 | 一般對話 |
| **高數值** | 輸出變化多樣 | 發想與創意寫作 |

### 核採樣值（Top_p）
- **功能**：調節隨機度的另一項核心參數（通常作為 Temperature 的替代調節方式）
- **機制**：模型僅在累積概率達到門檻值的詞彙集合中進行抽樣
- **典型數值區間**：**0.9 至 0.95**

## 4. 系統提示詞 vs 用戶提示詞

| 比較項目 | 系統提示詞（System Prompt） | 用戶提示詞（User Prompt） |
|----------|---------------------------|--------------------------|
| **主要目的** | 設定基本行為、角色、語氣及限制條件 | 提供即時查詢、請求或待執行的具體任務 |
| **持續性** | 靜態；通常由開發人員預先設定一次，在整個對話階段中保持不變 | 動態；隨每條訊息或每次互動而變動 |
| **可見度** | 在已推出的應用程式中，通常對終端用户隱藏 | 由終端用户直接輸入 |
| **約束力（權限）** | 較高；如同模型的「憲法」，模型受訓時已被設定為必須遵循 | 較低；必須在系統提示詞設定的框架範圍內運作 |

---

## 5. 系統提示詞架構公式：R-C-C-O

| 組件 | 說明 | 範例 |
|------|------|------|
| **R — 角色（Role）** | 定義 AI 的身份與受眾 | 你是一位 [特定專業角色] / 服務對象為 [受眾類型] |
| **C — 核心指令（Core Instruction）** | 定義主要職責與規則 | 你的主要職責為 [核心目標] |
| **C — 限制條件（Constraints）** | 設定必須遵守的限制 | 你必須：限制條件 1、限制條件 2 |
| **O — 輸出格式（Output format）** | 定義風格與語氣 | 風格 / 語氣 |

## 6. 實際測試範例

### 系統提示詞設定（航空客服）

> 你是一位航空公司的客戶服務助理。
>
> 規則：
> 1. 只根據已上載的知識庫文件回答問題，不可以使用其他來源的資訊。
> 2. 回答時必須清楚指出你依據的文件段落或政策條款編號。
> 3. 如果知識庫中沒有足夠資料回答問題，必須明確回答：「根據現有文件，我無法確認此資訊，建議聯絡客戶服務專員核實。」不可以自行推測或編造答案。
> 4. 所有回覆必須使用繁體中文，語氣專業、簡潔、有禮。

### 測試提問

| # | 提問 | 預期結果 |
|---|------|----------|
| 1 | 喪親優惠票申請需要準備甚麼文件？ | ✅ AI 根據知識庫引用政策條款編號，列出具體所需文件 |
| 2 | 我已經完成行程，可以追溯申請喪親優惠票退款？ | ✅ AI 引用政策條款，説明完成行程後不可追溯申請 |
| 3 | 香港最大的商場在哪裡？ | ✅ AI 回覆：「根據現有文件，我無法確認此資訊，建議聯絡客戶服務專員核實。」 |

## 7. 發布上線

### 步驟
1. 點擊「儲存並發布」（Save and Publish）
2. 選擇發布渠道（Release Channel）：
   - 免登入窗口（No login window）
   - API Access
   - Lark Robot / DingTalk Robot
   - WeChat Official Account Integration
   - Portal

### 建立分享連結
1. 點擊「建立新連結」（Create a new link）
2. 設定有效期限、QPM（每分鐘查詢數）、積分上限
3. 點擊「開始使用」（Start Using）即可複製分享連結

---

## 8. 積分扣除機制

| 項目 | 說明 |
|------|------|
| **扣除原則** | 積分直接自**開發者**（構建機械人的一方）帳戶中扣除，而非使用者端 |
| **主要優勢** | 開發者能完整追蹤與檢視使用者輸入的提問內容，以及機械人的實際回覆記錄 |
| **潛在代價** | 調用次數將直接消耗開發者自身的積分配額 |
