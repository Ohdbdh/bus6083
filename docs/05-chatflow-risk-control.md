# 模組五：Chatflow 風控架構

## 1. 為什麼需要 Chatflow？

### 傳統模式：單一巨型 Prompt 機械人

| 問題類別 | 具體問題 |
|----------|----------|
| **Token 量與運營成本** | 成本雪崩：每輪簡單對話都要全量發送包含所有業務規則、分支邏輯的 Prompt |
| | 延遲極高：長文本推理嚴重拖慢響應速度 |
| | 注意力稀釋：陷入 Lost-in-the-Middle，中間的禁令極易被忽略 |
| **系統穩定性與法律風險** | 用「概率」去賭「確定性」：大模型本質是隨機概率，分支越多（>5 條），違規胡說的幾率越高 |

### 進階模式：模組化 AI 聊天工作流（Chatflow）

| 優勢類別 | 具體優勢 |
|----------|----------|
| **Token 量與運營成本** | 任務解耦，隨用隨取：每個節點只需幾十個字專屬 Prompt |
| | 零 Token 節點：表單驗證由代碼完成，整體 Token 費用暴降 |
| | 極速響應：輕量節點實現毫秒級流轉 |
| **系統穩定性與法律風險** | 硬隔離：涉及金錢、退款、投訴強制繞過 LLM，直接轉人工或固定表單 |

## 2. Chatflow 架構概覽

AI 工作流程是一種**預先定義的、按步驟執行的任務序列**，其中人工智慧負責處理固定流程中的特定環節。

### 客服風控工作流架構

```
【用户發起提問】
        ↓
【意圖分類器 Intent Classifier】（自動判別問題類型）
        ↓
    ┌───┴───┐
    ↓       ↓
 分支 A    分支 B
 低風險    高風險財務
 業務      業務
    ↓       ↓
 RAG       固定回復
 知識庫    「您的訴求已收到，
 檢索 →     專員將在 24 小時內
 LLM       致電核實。」
 生成解答
```

## 3. 核心節點

### 節點一：問題分類器（Intent Classifier）

當學生提出不同類型的需求時，可透過問題分類節點處理。

- **模型**：可選 Llama-4-Maverick
- **分類 1**：低風險業務（行李額度 / 機上餐飲 / 登機時間）
- **分類 2**：高風險財務業務（喪親特惠 / 退票改簽 / 差價退款 / 法律索賠）

### 節點二：數據集節點（Dataset）

在工作流程中明確調用並檢索知識庫，精準控制 RAG 的調用時機與執行方式。

**節點配置：**
1. 選取欲檢索的數據集
2. 定義檢索詞（支援引入變數）
3. 選擇檢索模式（語義搜尋 / 全文搜尋 / 混合搜尋）

**配置範例：**
- 數據集：business
- 搜尋方法：混合檢索
- Top K：5000
- 相似度閾值：0.4
- 重排模型：Llama-4-Maverick

### 節點三：AI 對話節點（AI Chat）

將檢索所得的結果傳送至大型語言模型，透過變數提取相關資訊並重整輸出解答。

**節點配置：**
1. 選取模型（如 Deepseek-V4-Flash）
2. 設定系統提示詞（可自訂覆寫預設值）
3. 配置溫度值（Temperature）與最大生成長度（Max Tokens）
4. 定義輸出變數以儲存生成回覆

### 節點四：提示詞配置

- 必須在系統提示詞中明確指定如何調用輸入的變數
- 在提示詞編輯區輸入「**/**」，即可選取已設定的變數
- 變數將代表根據使用者輸入查詢所對應檢索出的知識庫內容

### 節點五：指定回復（Specified Response）

該模組可以直接回復一段固定的內容，常用於引導、提示。

**範例回復內容：**
> 您的訴求已收到，專員將在 24 小時內致電核實

## 4. 實際測試

| 測試問題 | 走哪條路徑 | 預期回覆 |
|----------|-----------|----------|
| 喪親優惠票申請需要準備甚麼文件？ | 低風險 → RAG 路徑 | AI 根據知識庫引用政策條款回答 |
| 我已經完成行程，可以追溯申請退款？ | 高風險 → 固定回復 | 「您的訴求已收到，專員將在 24 小時內致電核實」 |
