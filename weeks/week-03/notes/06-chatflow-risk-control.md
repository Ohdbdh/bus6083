# 6. 進階：Chatflow 風控架構

## 本節定位

- **上一節**：構建了一個能基於知識庫回答的聊天機械人
- **本節要解決的問題**：如何確保 AI 沒有機會越權處理退款、索賠等高風險業務？
- **學完你應該能夠**：設計一個帶意圖分類器的 Chatflow，將高風險業務硬隔離
- **關鍵詞**：Chatflow、意圖分類器（Intent Classifier）、硬隔離、Lost-in-the-Middle

---

## Chatflow 的核心不是讓 AI 更聰明，而是讓 AI 沒有機會越欄

上一節的 RAG 聊天機械人能處理一般查詢，但企業客服中有些問題涉及**金錢、退款、法律索賠**——這些高風險業務不能讓 AI 自由回答。

> **Chatflow 的核心不是讓 AI 更聰明，而是讓 AI 沒有機會越欄。**

換句話說，與其相信 AI「會遵守規則」，不如直接讓它「沒有機會觸碰」高風險業務。

### 傳統模式：單一巨型 Prompt 機械人

把所有規則塞進一個超長的系統提示詞，看起來簡單，實際上問題重重：

| 問題 | 說明 |
|------|------|
| **成本雪崩** | 每輪對話都要全量發送包含所有規則的 Prompt |
| **延遲極高** | 長文本推理拖慢響應速度 |
| **注意力稀釋** | 陷入 Lost-in-the-Middle，中間的禁令容易被忽略 |
| **概率賭確定性** | 分支越多（>5 條），LLM 違規胡說的幾率越高 |

### 進階模式：模組化 Chatflow

| 優勢 | 說明 |
|------|------|
| **任務解耦** | 每個節點只需幾十個字專屬 Prompt |
| **零 Token 節點** | 表單驗證由代碼完成，不消耗 Token |
| **硬隔離** | 涉及金錢、退款、投訴的業務強制繞過 LLM，轉人工或固定表單 |
| **極速響應** | 輕量節點實現毫秒級流轉 |

## Chatflow 風控架構

核心思路：用**意圖分類器**將問題分為低風險和高風險兩條路徑。

```
【用户發起提問】
        ↓
【意圖分類器 Intent Classifier】
        ↓
    ┌───┴───┐
    ↓       ↓
 低風險    高風險
 （查詢）  （退款/索賠）
    ↓       ↓
 RAG       固定回復
 知識庫    「您的訴求已收到，
 檢索 →    專員將在 24 小時內
 LLM       致電核實。」
 生成解答
```

### 分類標準

| 分類 | 問題類型 | 處理方式 |
|------|----------|----------|
| **低風險** | 行李額度、機上餐飲、登機時間 | RAG 知識庫檢索 → LLM 生成回答 |
| **高風險** | 喪親特惠、退票改簽、差價退款、法律索賠 | 繞過 LLM，直接固定回復或轉人工 |

## 核心節點配置

### 節點一：問題分類器（Intent Classifier）

- 模型：Llama-4-Maverick
- 讀取用户問題，自動判別類型
- 輸出分類 1（低風險）或分類 2（高風險）

### 節點二：數據集節點（Dataset）— 僅低風險路徑

| 配置項 | 值 |
|--------|-----|
| 數據集 | business（或自建知識庫） |
| 搜尋方法 | 混合搜尋 |
| Top K | 5000 |
| 相似度閾值 | 0.4 |
| 重排模型 | Llama-4-Maverick |
| 檢索詞 | 流程開始 > 用戶問題 |

### 節點三：AI 對話節點（AI Chat）— 僅低風險路徑

| 配置項 | 值 |
|--------|-----|
| 模型 | Deepseek-V4-Flash |
| 系統提示詞 | 航空客服模板（使用「/」插入知識庫引用變數） |
| Temperature | 0.2 |
| Max Tokens | 1000 |

在提示詞中輸入「**/**」可選取已設定的變數：
- `知識庫搜索 > 知識庫引用`（檢索結果）
- `流程開始 > 用戶問題`（用户輸入）

### 節點四：指定回復（Specified Response）— 僅高風險路徑

固定回復內容：
> 您的訴求已收到，專員將在 24 小時內致電核實

## 實際測試

| 測試問題 | 預期路徑 | 預期回覆 |
|----------|-----------|----------|
| 行李額度是多少？ | 低風險 → RAG | AI 根據知識庫回答 |
| 我想申請退款 | 高風險 → 固定回復 | 「您的訴求已收到...」 |
| 登機時間是幾點？ | 低風險 → RAG | AI 根據知識庫回答 |
| 我要法律索賠 | 高風險 → 固定回復 | 「您的訴求已收到...」 |

> **Checkpoint 6**：用「退款 / 索賠 / 投訴」類問題測試，確認它們**不會**進入 AI 對話節點，而是直接走固定回復路徑。

> **Checkpoint 7**：用「行李 / 餐飲 / 登機時間」類問題測試，確認它們**會**走 RAG 路徑並返回知識庫內容。
