# 8. UI/UX & Vibe Coding

本節是獨立的技能模組，不屬於 RAG 主線，但與 AI 應用開發密切相關。

## 什麼是 UI/UX？

| 概念 | 定義 | 關注點 |
|------|------|--------|
| **UI（User Interface）** | 應用程式的「外觀」 | 顏色、字型、佈局、按鈕 |
| **UX（User Experience）** | 應用程式的「使用感受」 | 是否易於操作？邏輯是否清晰？速度是否流暢？ |

> **良好的設計並非裝飾，而是溝通。**

| 情境 | 評價 |
|------|------|
| 精美但導航混亂 | 糟糕的 UX |
| 簡潔但精準滿足需求 | 優秀的 UX |

## Vibe Coding：用自然語言寫程式

### 舊模式 vs 新模式

| 比較項 | 舊模式 | 新模式 |
|--------|--------|--------|
| 技能 | 學習 HTML/CSS/JS（數月） | 以語言描述（數分鐘） |
| 成本 | 聘請開發人員 | 向 AI 發出指令（免費） |
| 除錯 | 逐行修復 | 告知 AI 哪裡出了問題 |
| 版本管理 | 需要版本控制 | 透過對話疊代 |

### Vibe Coding 流程

1. 用自然語言描述應用程式
2. AI 生成可運作的 HTML/CSS/JS
3. 即時預覽結果
4. 透過對話要求修改
5. 重複直到滿意
6. 複製程式碼 / 分享連結

## 網站生成 Prompt 公式

### 四大要素

| 要素 | 說明 |
|------|------|
| **目的與主題** | 明確定義網站目標 |
| **內容結構** | 指定所需內容與頁面 |
| **功能需求** | 進度追蹤、互動式彈出視窗、動態資訊 |
| **視覺風格** | 描述設計美學 |

### 簡短模板

```
建立一個 [頁數]-頁的網站，主題為 [目的]。
受眾：[對象]。風格：[風格]。
圖片：圖片網址。手機響應式設計。
```

### 完整模板

```
建立一個 [頁數]-頁的網站，主題為 [目的]。
目標受眾：[對象]。
頁面：[頁面列表及簡短說明]。
關鍵功能：[功能列表]。
圖片：使用如 Unsplash 等免費線上圖庫。
風格：[風格]。主色調：[色盤]。字型：[字型描述]。
手機響應式設計。包含導航選單。
```

### 風格選項

極簡風格、深色模式、紅金傳統風、粉彩可愛風、復古報紙風、企業專業風、像素藝術、卡通、極簡平面風、深色霓虹風

### 使用自己的圖片
提供圖片網址（Google Search / Unsplash / Google Drive 連結），並告知 AI 放置位置。

## 常見錯誤與修復

| # | 錯誤 | 修復方法 |
|---|------|----------|
| 1 | 按鈕無反應 | 描述具體錯誤給 Gemini，要求修正程式碼；無效則重新生成 |
| 2 | 圖片不正確 | 要求 Gemini 使用免費圖庫，或直接貼上圖片網址 |
| 3 | 無法儲存進度 | Gemini Canvas 目前不支援帳號登入與進度儲存 |

## 實戰範例：智能排班系統

### Prompt 指令

> 請在 Canvas 中幫我構建一個現代極簡風格的【員工報更與智能排班系統】，單頁面 HTML/JS 原型：
>
> 1. 員工端：輸入姓名工號，勾選空閒時段（早班/午班/晚班）
> 2. 管理員端：儀表板展示熱力圖，一鍵智能排班（每班至少 2 人），高亮人手不足時段

### 成效
- 學生可在瀏覽器直接交互測試
- 從想法到可用原型，耗時不到 3 分鐘
